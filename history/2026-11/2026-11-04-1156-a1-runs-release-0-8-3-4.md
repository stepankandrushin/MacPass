# a1 runs the release 0.8.3.4 from /Applications, Auto-Type works again

Global Auto-Type did nothing on a1. The MacPass running there was the Debug build in
build/Build/Products/Debug (0.8.2, build 27120-main), built and started at 2026-11-03 22:37:13 by another session
with pass.kdbx open. `scripts/run.sh` signs ad hoc, so its designated requirement is its cdhash. a1's Accessibility
grant for `io.github.stepankandrushin.MacPass` (TCC, 2026-10-23 17:51) is keyed to the Developer ID requirement
(`anchor apple generic … certificate leaf[subject.OU] = "38LK44494Q"`). macOS therefore saw the Debug build as an
app with no grant: it has the same bundle ID but does not meet that requirement.

The fix:

- pass.kdbx was not edited (no "Edited" in the title). The Debug build was quit with NSRunningApplication terminate.
- The notarized 0.8.3.4 (build 27100, the latest release) from build/release/dmg was copied with `ditto` to
  /Applications/MacPass.app (Gatekeeper: Notarized Developer ID) and started. Before this, a1 had no copy in
  /Applications.
- Its Autotype Doctor shows Accessibility granted. pass.kdbx reopened locked, waiting for the owner to unlock it.
  Settings are unchanged: EnableGlobalAutotype on, the hotkey unchanged, AllowScreenshots on, FileChangeStrategy
  unset (Merge in 0.8.3.4).

On a1, test Auto-Type with a Developer ID build (/Applications, or `scripts/release.sh --no-publish`). An ad hoc
`scripts/run.sh` build does not have the grant. Granting Accessibility to one would replace the release's entry,
because TCC keeps one entry per bundle ID.
