# Release 0.8.3.6: search ignores spaces, tabs and line breaks around the text

On the owner's word, main (4ba54a50, history/2026-11/2026-11-07-1000-search-trims-spaces-around-text.md) was pushed
to the fork and published with `scripts/release.sh 0.8.3.6` from a1 as
https://github.com/stepankandrushin/MacPass/releases/tag/0.8.3.6 (build 27190, tag at 4ba54a50). The build, signing
and both notarizations (the app, then the DMG) went through on the first try.

- The DMG on the release has the same SHA-256 as the build in build/release (`7014968e…`), and Gatekeeper accepts it
  as Notarized Developer ID.
- The appcast at https://stepankandrushin.github.io/MacPass/appcast.xml listed 0.8.3.6 (27190) at 10:25, a minute after
  the release. Every Mac on the fork gets it through Sparkle's daily check, which asks before installing, or now through
  MacPass > Check for Updates. Nothing was installed: a1 still runs 0.8.3.5 from /Applications.
- The release notes list the commits since 0.8.3.5: this change and the history entry of 0.8.3.5.

scripts/build-local.sh, release.sh and run.sh had lost their executable bit on disk (the change time is 2026-11-06
around 22:16; who did it is unknown). Git saw them as changed, and release.sh refuses to run with changes in the tree.
The files were left as they are; the release ran with `GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=core.fileMode
GIT_CONFIG_VALUE_0=false`, so git ignored file modes for that run only. The mode changes and the untracked .pi/ are
still uncommitted.
