# Release 0.8.3.4, and the fork on pro

On the owner's word, main (c90a995e and its history entry) was pushed to the fork and published with
`scripts/release.sh` from a1 as https://github.com/stepankandrushin/MacPass/releases/tag/0.8.3.4 (build 27100): a
database open on several Macs is merged without asking and left unedited when the merge brings nothing, so autosave
no longer sends it back and forth (history/2026-11/2026-11-03-2105-merge-saves-from-other-macs.md). a1 had everything
the script needs: the Developer ID identity, the `notarytool-password` keychain profile and the Sparkle key in infra
secrets/macpass; signing and both notarizations went through on the first try. GitHub Pages served the new appcast
within about 90 s of the push.

- a3 (fork 0.8.3.3, running since 2026-10-24, FileChangeStrategy unset) fetches the appcast with 0.8.3.4. Its Sparkle
  checks daily and asks before installing (SUAutomaticallyUpdate off); the last check was 2026-11-03 00:30, so the
  update alert comes about 00:30 on 2026-11-04, or now through MacPass > Check for Updates.
- pro (Mac Pro, macOS 26.6.2) ran upstream 0.8.1, not open. The DMG from the release (SHA-256 the same as the build)
  was checked by Gatekeeper and installed in /Applications/MacPass.app; upstream's app is in pro's Trash as
  `MacPass 0.8.1 (upstream).app`. Upstream's settings (`com.hicknhacksoftware.MacPass`, 13 keys: last database,
  window frames, toolbar, search) were copied into `io.github.stepankandrushin.MacPass` without its Sparkle keys; the
  fork has automatic checks on and installing on ask, as on a3. FileChangeStrategy is unset there too, so Merge.
  Not launched; global Auto-Type was never on there, so it needs no Accessibility grant yet.

Cairn's deployment notes let `pass.kdbx` join `~/c` once every Mac that keeps it open runs this fork; that is a3
only, so once a3 has installed 0.8.3.4. Not done: the upstream pull request, and the test on two Macs with the owner.
